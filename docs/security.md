# 安全、权限与私有 API 边界

## 1. 安全结论

LanExtend v0.2.0 是**无认证的可信内网 MVP**。只有在你控制网络、信任同网设备并能限制防火墙范围时才应运行。它不适合公网、端口转发、共享 VPN、访客 Wi‑Fi、酒店/机场网络、校园网或无法识别其他终端的办公网。

“Mac 主端权限最高”目前表示：

- 只有主端 GUI 能创建/销毁 macOS 虚拟显示器；
- 正常流程由主端主动连接、选择捕获源并断开；
- 子端同时只接受一个主端会话。

这不是密码学权限体系。协议没有账号、密码、配对码、证书、设备公钥、签名广播或访问控制列表。

## 2. 当前保护与缺口

| 控制 | 当前实现 | 能解决 | 不能解决 |
| --- | --- | --- | --- |
| 私有 IPv4 校验 | 手动目标仅允许私网/回环/链路本地 IPv4 | 减少误填公网 IP | 同网恶意设备、DNS/路由劫持、SSRF 完整防护 |
| 消息解析与大小限制 | 发现 4 KiB、信令 256 KiB，严格类型/字段 | 一部分畸形消息和内存放大 | 逻辑攻击、频率型 DoS、解析器/底层库漏洞 |
| 单会话限制 | 子端只接受一个活动主端 | 避免正常并发争用 | 抢先连接占用、身份认证 |
| Electron 隔离 | context isolation、sandbox、无 Node integration、IPC 白名单 | 降低渲染页面直接获得系统权限的风险 | Electron/Chromium 漏洞、错误新增 IPC |
| WebRTC DTLS-SRTP | 标准加密媒体通道 | 媒体链路窃听/篡改的一部分风险 | SDP 通过未认证信令交换，无法确认对端身份，仍可能中间人替换 |
| 本机配置 | 原子写入；类 Unix 请求 `0600` | 避免部分损坏和普通同机用户读取 | Windows ACL 保证、磁盘加密、恶意管理员、本机木马 |
| 私有 API 子进程隔离 | helper 单独运行、运行时探测 | 降低 helper 失败拖垮 GUI 的概率 | 私有 API 变化、系统崩溃、Apple 支持/审核 |

## 3. 威胁模型

### 受保护资产

- Mac 虚拟显示器上的屏幕内容；
- 设备名称、内网地址、最后连接时间和使用习惯；
- Windows 子端显示窗口和会话可用性；
- 两端本机应用权限及软件供应链完整性。

### 假设

- Mac、Windows 操作系统和当前登录用户可信；
- 局域网由使用方控制，同网只有受信设备；
- 安装包来自可信提交/构建，并经过操作者核对；
- 攻击者不能以管理员/root 控制端点。

任一假设不成立时，v1 不提供足够防护。

### 主要威胁

| 威胁 | 当前风险 | 例子 | MVP 处置 |
| --- | --- | --- | --- |
| 伪造子端 | 高 | 攻击者广播相同名称/UUID，诱导主端连接并接收画面 | 仅靠网络隔离和人工核对 IP；记忆列表不可信 |
| 伪造主端/抢占 | 高 | 任意同网 WebSocket 客户端先连子端，占用单会话或发送 SDP | 防火墙限制来源子网；使用后退出子端 |
| 信令中间人 | 高 | 篡改明文 offer/answer/ICE，替换 WebRTC 指纹/候选 | v1 无协议级修复；只能用受控交换网络 |
| 屏幕误选 | 高 | 用户误选主屏，泄露聊天、密码或通知 | 建链前用无敏感测试窗口确认捕获源 |
| 拒绝服务 | 中 | 广播洪泛、连接抢占、超频消息、端口占用 | 大小/单会话限制；防火墙/VLAN 隔离 |
| 本机配置泄露 | 中 | 读取 `settings.json` 得到内网拓扑和时间 | 磁盘加密、用户 ACL、不要记录敏感设备名 |
| 未签名包替换 | 高 | 下载的 artifact 被替换或来自错误提交 | 仅从可信 Actions 记录下载并核 SHA；正式发布签名 |
| 私有 API 失效 | 可用性高 | macOS 更新后类/selector 改变，显示创建失败 | 运行时 probe、子进程隔离、目标系统回归 |

## 4. 推荐部署基线

1. 使用独立家庭实验网络或专用 VLAN；阻止不受信 VLAN 到 Windows 信令端口。
2. Windows 网络配置文件设为“专用”。防火墙仅允许 LanExtend 在专用网络运行：子端出站 UDP `47771` 广播、从 Mac 固定 IP/子网接收入站 TCP 信令，以及双向 WebRTC 动态 UDP。Mac 端只在可信网络接收发现广播。
3. 不在路由器做 UDP/TCP 端口转发；不通过 frp、ngrok、Tailscale 共享网段或其他隧道暴露 v1。
4. 在 Mac 与 Windows 实体旁完成首次配对式人工确认：核对主机名、IPv4 和画面测试内容。
5. 投放前关闭敏感通知，先把无敏感测试窗口移动到虚拟显示器，确认子端内容。
6. 使用完毕后主端断开并销毁虚拟显示器，子端退出应用。
7. 保持 macOS、Windows、Electron 和依赖更新；更新后重新执行双机验收。

网络 ACL 示例原则：

```text
允许  Mac_IP -> Windows_IP TCP/47772
允许  Windows_子网内广播 -> Mac UDP/47771（若需要自动发现）
允许  Mac_IP <-> Windows_IP WebRTC 动态 UDP（按应用/受控端点限制）
拒绝  其他 VLAN/公网 -> Windows TCP/47772
```

具体防火墙命令因组织策略而异，不在应用中自动创建高权限规则。

## 5. macOS 权限

### 屏幕录制

捕获扩展显示器需要系统屏幕录制授权。用户拒绝时应保持失败关闭，不应尝试绕过 TCC。修改授权后通常需要完全退出并重开应用。

系统会显示屏幕正在被捕获的隐私指示，这是正常且不可隐藏的安全提示。

### 本地网络

自动发现和连接需要局域网访问。应用的打包配置包含用途说明；不同 macOS 版本是否弹窗及文案可能不同。

### 不申请的权限

MVP 不需要辅助功能、输入监控、麦克风、摄像头或系统扩展。若未来增加键鼠/触控或音频，必须重新做威胁模型、最小权限设计和用户可见开关。

## 6. `CGVirtualDisplay` 私有 API

macOS 主端通过运行时类名使用未公开的 `CGVirtualDisplay`、`CGVirtualDisplayDescriptor`、`CGVirtualDisplayMode` 和 `CGVirtualDisplaySettings`。因此：

- Apple 没有兼容性、稳定性或审核承诺；
- macOS 小版本/大版本更新都可能导致 helper 失败或行为变化；
- 项目应把支持基线明确限定为 **macOS 14+ 且逐版本实测**；
- 不能把 `--probe` 成功等同于显示创建、捕获和释放全部正确；
- 该实现不支持 Mac App Store 分发；应采用站外 Developer ID 签名、公证和清晰披露；
- helper 不应要求关闭 SIP/AMFI，也不应被赋予不必要的 root 权限。

如果组织政策禁止私有 API，本项目不适用；可改用物理/虚拟显示驱动、官方 Sidecar/AirPlay 方案或只做屏幕镜像，但产品能力会不同。

## 7. 未签名构建与供应链

当前 GitHub Actions artifacts 只用于开发验收；GitHub Releases 可分发维护者选定的候选包：

- 没有 Apple Developer ID 签名/公证；
- 没有 Windows Authenticode 签名；
- 没有发布证书固定、静默自动安装、SBOM 或独立可复现构建声明；
- workflow 中的 `npm ci` 会从 npm registry 获取锁定包，仍需供应链治理。

应用的版本检查只向 `api.github.com/repos/Modole/LanExtend/releases/latest` 请求公开发布元数据；遇到 API 速率限制时，只解析本仓库 `/releases/latest` 的 HTTPS 重定向。应用只允许打开本仓库固定的 HTTPS Releases 页面。请求不会上传设备 UUID、局域网地址、设置或画面，但 GitHub 仍会看到普通 HTTPS 请求所包含的公网 IP 和网络元数据。安装包不会自动下载或执行，用户必须自行核对发布说明与 SHA-256 后安装。

不要指导普通用户长期关闭 Gatekeeper/SmartScreen。内部测试可以在确认提交、构建日志和哈希后使用系统提供的单次“仍要打开”流程。正式发布必须配置签名、证书保护、公证、哈希、依赖扫描和回滚。

直接依赖和研究参考见[第三方声明](../THIRD_PARTY_NOTICES.md)与[开源调研](open-source-research.md)。GPL/AGPL 项目只可作为概念参考；复制代码可能改变本项目分发义务。

## 8. 认证版本的最低设计要求

在离开受控内网 MVP 前，建议设计不兼容的协议 v2，并至少包括：

- 首次带外配对码，双方生成并持久化设备密钥；
- 基于设备公钥的双向认证和可读指纹确认；
- WSS 或等价认证加密信令，并绑定 WebRTC DTLS 指纹；
- 广播只做发现候选，连接后验证已配对身份；
- 子端明确的连接确认、受信主端列表、撤销和“拒绝新配对”模式；
- nonce、过期时间、重放保护、连接/消息速率限制；
- 安全日志，但默认不记录 SDP、ICE、屏幕内容和敏感设备名；
- 密钥存储使用 macOS Keychain/Windows DPAPI，而不是明文 JSON；
- 针对降级、MITM、抢占、重放、洪泛和配置迁移的自动化/渗透测试。

仅在 v1 信令里增加一个长期共享密码不足以形成上述安全属性。

## 9. 漏洞报告建议

公开仓库尚未定义私密安全报告通道时，不要在公开 issue 中粘贴屏幕截图、私网 IP、完整 SDP/ICE、设备 UUID 或日志。维护者应在首次公开发布前增加 `SECURITY.md`、支持版本、私密联系方式和响应时限。
